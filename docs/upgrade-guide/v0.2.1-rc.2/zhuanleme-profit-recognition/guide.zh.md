# 赚了么费用归属与结算口径

[English](guide.md) | 中文

## 变更

本地赚了么产品将账本 `user_version` 从1或2升级到3，不改写已有账目、规则、审计或请求记录。旧读取器拒绝版本3。JSON导出使用版本3，新读取器同时接受版本2备份。客户完整备份接受两代SQLite文件。

新实际成本默认 `costCoverage: partial`，用户明确确认该类成本已录全后才计算数值利润。历史实际成本保留原计算结果，重新核对前标为暂算。包含 `costFrom` 和 `costTo` 的费用按实际所属期间替换估算，不受付款日期影响。已有月度规则的实际成本必须明确所属期间，或明确指定 `costTiming: daily`。

净到账必须提供 `revenueBasis: net` 和 `platformFee`，系统还原营业额并扣费一次。同渠道手动平台费与重叠的平台固定估算被拒绝。报告新增 `profitStatus`：`incomplete`待补全、`provisional`暂算待核对、`estimated`含估算、`verified`已核对。存在数值不代表利润已经核对完整。

## 迁移

1. 停止写入，备份完整Profile、客户账本目录及身份数据库后再启动版本3。降级时一起恢复代码与数据，不用旧产品读取新数据。
2. 在表格行的核算入口、客户录入字段或模型工具参数中明确成本完整性和费用日期。部分票据不得标为全部成本已录全。历史记录保留，修改前先核对其实际含义。
3. 每笔净到账同时填写已扣平台费，退款同时填写退回的平台费。转换已有收入为净到账前，先处理同渠道重复的平台费；其他渠道的手动费用使用 `feeChannel`。
4. 配置收入渠道并逐日核对，包括确认零收入渠道。展示和回答利润时同时披露 `profitStatus`；固定额和比例成本仍标为估算。
5. 运行产品测试和外层项目的 `scripts/test-monthly-ledger.mjs`，验证日报、期间报表、重试、修改、退款和恢复。月度测试使用临时账本，不调用模型。
