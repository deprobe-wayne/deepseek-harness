# 赚了么经营 Harness 检查 · 2026-09-22

检查范围为本地 `product/zhuanleme` 插件、官方公开会话/工作区接口，以及临时 Web Profile 中的运行行为。修复没有改动官方 `packages/`、`apps/` 或真实店铺账本。

## 本轮修复

| 问题 | 原因与修复 |
| --- | --- |
| 对话无法归档、删除 | 自定义侧栏只绘制标题。现接入官方归档/取消归档，并增加持久的「已删除」和恢复入口。删除为可恢复操作，保留原始对话及经营数据。 |
| 只能看到前六个对话 | 固定截断改为显示更多和标题搜索；最近、已归档、已删除分别可查询。 |
| AI 入账须到经营总览确认 | 三类业务工具提供对话卡片，读取认证 API 的最新账目状态。点击确认直接生效，账表同步更新。 |
| 对话结束后卡片被折叠 | 宿主紧凑模式会折叠工具过程。利用公开的回合末尾插槽保留本轮确认卡片，按原生调用树读取并去重，兼容 PTC 子调用。 |
| 路径别名使旧对话丢失店铺 | 前端原来只比较 cwd 字符串。现在优先采用官方 Session 与 Workspace 归属，支持 `/var` 与 `/private/var` 等同一路径别名。 |
| 确认成功但网络响应丢失后重试报错 | 相同的最后一次确认/撤销允许幂等重试；发生后续修改后仍拒绝旧版本。 |
| 编辑后创建请求的去重依据变化 | 以首次创建审计核对原始请求内容；编辑和重启后仍保持同一业务请求的身份。 |
| 旧成本规则表单覆盖新规则 | 表单记录打开时的规则与版本，Host 在事务内核验；版本过期时保留错误并要求重开表单。 |
| 明确 0% 成本被当作缺失 | 0% 按零计算；非零费率的收入基数未报时继续保持缺失。 |
| 新建对话的失败不能回传 | 改用可等待的官方 `openWorkspace`，错误可以回到侧栏。 |

卡片确认使用用户看到的版本，不在点击时悄悄接受新版本。重复点击只提交一次；失败后读取当前内容供重新核对。历史卡片重新打开时显示真实的已入账/已生效/已放弃状态。窗口卸载、切店和过期网络结果不会继续更新旧界面。对话归档或删除不撤销已入账内容，也不丢弃待确认草稿。

## 仍需补齐的经营能力

| 优先级 | 缺口与影响 | 建议 |
| --- | --- | --- |
| 高 | 缺少产品化备份、导出和恢复入口。当前持久化依赖本地 SQLite；数据库文件存在不等于有可恢复的异地副本。 | 增加包含账本、审计和对话状态的一致备份，提供导出和恢复演练。 |
| 高 | 多渠道收入没有完整性标记。只报一个渠道时，汇总便能形成收入合计，按全店营业额计算的成本可能基于不完整收入。 | 店铺配置启用渠道，日结时区分已报、明确为零和未报；完整性不足时标记汇总。 |
| 中 | 金额只接受非负数，净退款日无法记录为负营业额；目前没有退货、冲销及结算差异的独立业务模型。 | 增加退款/调整类型和原始单据关联，明确影响收入与成本的口径。 |
| 中 | 审计保存在数据库中，界面没有修改历史查看和对账工作流。 | 增加账目版本历史、操作记录及按日对账。 |
| 中 | 卡片确认是业务工具的交互约束，当前 Profile 仍提供通用文件/终端能力；不是按角色隔离的财务审批系统。 | 如需多人/托管经营使用，将账本写权限移到受控服务并设计角色和操作授权。 |
| 当前范围外 | 采购不等于耗用或付款；没有库存/BOM、跨期实际成本分摊、应收应付、平台待结算和实际现金流。 | 按经营场景逐项设计，避免把现有利润估算当作完整会计或现金流报表。 |

当前适合单机、人工核对的经营记录与成本估算；长期正式经营使用应优先补齐备份恢复与收入完整性。

## 验证与边界

运行命令使用外层附带的 Node 24：插件构建、`node --test product/zhuanleme/tests/*.test.mjs`、`node product/zhuanleme/tests/profile-smoke.mjs --browser`。单元测试覆盖账本事务、店铺隔离、网络重试、冲突、卸载、对话状态持久化和确认卡片。隔离 Profile 使用真实 Loader、AgentLoop、ToolRuntime、SQLite 与官方 Web 客户端，外部推理由脚本模型替代；Native 和 PTC 的持久结果均校验卡片标识。

本轮结果：45/45 单元测试通过，Client 构建通过，隔离 Profile + Chrome 页面回归通过。桌面 1440×1000 与模拟手机视口 390×844 检查了聊天确认；实际点击确认新增、账目修改和规则修改后独立查询 SQLite，验证立即生效。刷新后卡片显示终态；归档、取消归档、删除后刷新、恢复对话均通过，并断言账目、规则和审计没有因对话操作而变化。未认证业务 API 返回 401。

页面证据为 [桌面对话确认](evidence/audit/conversation-review-desktop.png)、[手机对话确认](evidence/audit/conversation-review-mobile.png) 和 [已删除列表](evidence/audit/conversation-deleted-desktop.png)。结果摘要见 [Profile 验证](evidence/profile-smoke.json)。手机为 Chrome 视口模拟，未做实体手机或完整深色界面验收。

本轮没有重新调用真实外部模型，没有运行官方全量测试和跨平台发布矩阵，也没有接入官方顶层录制会话快照门禁。英文界面仍有既有中文回退，尚未完成全量翻译。此前真实模型验证的摘要保留于 `evidence/live-model-smoke.json`，不能代替本轮页面验证。

本地 Web Profile 采用链接加载；Client 已构建，Host 代码需要重启 DSH 服务后生效。运行 `start-deepseek.command` 前停止旧服务，之后刷新页面。

## 本地项目与表格交互追加验收

店铺、对话列表各自折叠，最近对话悬停显示置顶/归档，置顶写入独立对话状态数据库并在刷新后保持。新增测试覆盖置顶重复请求、跨店拒绝、非法参数、重启持久化和排序。每店是有本地文件夹的工作区；账本数据库集中保存并按店隔离，总览/明细固定属于店铺。

记账表支持直接新增及编辑，显示日期、项目、类型/归属和金额，不显示状态列。Chrome 回归实际录入 123.45 元，修改到 130.25 元，独立查询 SQLite 验证金额与版本；Esc 取消 999 元的修改，刷新后仍为 130.25 元。截图见 [桌面记账表](evidence/audit/ledger-grid-desktop.png) 与 [手机记账表](evidence/audit/ledger-grid-mobile.png)。这是单元格编辑流程，尚未提供 Excel 的批量粘贴、公式或填充柄。
