# 赚了么

## Platform
web

## Users and purpose
面向小型零售及餐饮店经营者的通用经营应用。用户按店铺维护持续保存的利润成本账本，通过手动录入，或在 AI 对话内核对确认卡片后入账，再查询、分析和导出经营数据。进入店铺先显示欢迎面板；打开经营总览或账目明细后，数据与官方 AI 对话同时可见。

## 产品与交付方向

以统一的网页应用作为主要产品，先通过受邀试用验证真实记账需求，逐步完善正式使用能力。试用与正式使用共用业务核心，试用范围和额度由产品配置控制。通用型指目标店铺共用同一产品和核心流程，首版围绕记账、票据核对、成本与经营分析展开。

标准产品优先承接多数目标店铺反复出现的需求。特殊客户需求按配置、可复用扩展、专属开发三个层级评估；专属开发明确交付内容、报价、验收和后续维护责任。App、本地部署和私有部署根据客户对离线、隐私或设备能力的实际需要另行评估。

产品核心保持统一，客户差异优先通过配置和插件表达。客户专属模块明确依赖版本和升级责任，共性缺陷修复与安全更新继续由统一核心提供。

## 网页首版范围

首版的使用闭环是创建店铺、录入账目、核对 AI 草稿、查看经营数据、导出和找回历史。桌面与手机浏览器均需完成主要操作。

| 范围 | 首版目标 |
| --- | --- |
| 记账与核对 | 手动录入、文字与小票识图、明确确认后入账、修改、撤销与历史查询 |
| 经营分析 | 收入与成本口径、数据完整性提示、期间查询和导出 |
| 客户访问 | 受邀客户登录，服务端校验客户对店铺、会话、附件、备份和业务操作的访问权限 |
| 调用保障 | 受控模型调用、客户额度、并发限制、超时和失败提示 |
| 数据与运行 | 自动备份及恢复验证、运行诊断、部署说明和版本更新流程 |

首版先验证单个店主使用的完整流程。多人角色、库存/BOM、应收应付、完整财务系统、原生 App 和复杂计费套餐根据实际需求排期。语音沿用现有本地识别能力，但线上录音所需的 HTTPS、认证、服务隔离和容量须单独验收。

## 定制需求处理

| 需求类型 | 处理方式 |
| --- | --- |
| 多数目标店铺共同需要 | 进入标准产品优先级评估，由产品核心统一维护 |
| 品牌、分类、成本规则、报表偏好等差异 | 优先评估配置支持，配置能力缺失时明确开发范围 |
| 外部系统对接或行业专用流程 | 评估为可复用插件，明确数据权限、接口依赖和升级责任 |
| 单个客户的独有需求、App 或私有部署 | 单独评估和报价，约定交付、验收与维护范围 |

客户需求的评估依据包括使用频率、共性、付费意愿、开发成本和持续维护成本。定制功能不得绕过账本事务、客户权限或用户确认机制。

## 开发顺序与验收

1. 固定标准产品的核心流程，把产品单测、Profile 冒烟和浏览器关键流程纳入产品发布检查。
2. 设计线上客户访问与部署方式，落实客户身份、服务端授权、数据和执行环境隔离、模型密钥管理与额度控制。现有店铺范围校验不能替代客户授权。
3. 补齐自动备份、恢复演练、错误诊断和手机浏览器验收，开放少量受邀客户真实使用。
4. 根据持续使用、录入纠错、模型成本、支持工作量及付费意愿调整标准产品，再扩大访问范围。
5. 对明确的特殊需求承接定制开发，并评估其中可纳入通用配置或插件的部分。

受邀客户录入真实数据前，必须验证跨客户访问拒绝、模型额度限制、备份恢复和故障诊断。对外说明数据存储位置、模型调用的数据范围、导出与删除方式。部署环境、客户登录方式和模型费用承担方在上线设计中明确。

## Confirmed constraints
使用用户提供的赚了么 Logo。店铺映射到 DSH 工作区，每店多会话共用账本。采购不等于耗用成本；金额用整数分计算；缺失不当作零；人工确认 AI 草稿后才成为账目。当前实现是本地 DSH 实例的账本，网页交付和客户定制是产品方向；线上客户权限及运营保障按上文验收后才能对外提供。当前能力不包括 SaaS 多租户权限、库存或完整会计系统。

## 当前体验
零售演示店「青禾生活」包含截至上海当天连续 30 天的虚拟销售、采购与六类实际成本记录，三个收入渠道包含周末高峰与日间波动；自动补齐新日期并保留已有修改与撤销；演示店与真实店铺按工作区隔离，并在报告中标记 demo。总览使用流水与成本叠加柱、利润折线组合图与成本环形图；明细使用 Material React Table 切换收入／支出表，支持搜索、排序、单元格录入修改及 Excel / CSV 导出；AI 草稿通过对话确认。

## 对话与核对
店铺对话支持归档、取消归档、移至已删除及恢复，并可搜索和展开更早历史。删除为可恢复移除，不擦除原始对话或经营账本。AI 新增账目、修改/撤销账目和成本规则均在对应对话中显示确认卡片；卡片显示当前店铺、日期、金额、修改前后内容和处理状态。确认直接生效，账表同步更新。

## 店铺项目与直接记账
每店对应本地项目文件夹；经营总览、账目明细和智能经营是同级入口。智能经营默认收起，展开后直接显示各个聊天，最右侧加号新建本店对话；归档与已删除对话从标题更多菜单进入独立管理窗口。店铺和智能经营分别可折叠；最近对话悬停显示归档和更多操作，置顶位于浮动菜单中并持久保存。账目明细以按钮切换收入表和支出表，营业收入归收入、采购及实际成本归支出；桌面列为营业日期、发生时间、项目、金额、渠道或类型、操作；手机优先项目和金额。点击无框编辑并自动保存，Esc 取消；删除常显居中，可从持久历史恢复。新增为表内无框录入，工具栏保留简短新增入口，成本规则不占据明细界面。更多菜单提供历史、期间报表、日结、备份和可选业务字段。账本仍在本地 Profile SQLite 内按店隔离。

## 录入与分析
对话默认录入，顶部可随时在空闲时切换录入与分析，店铺首页提供两种模式入口。模式按对话持久保存；录入支持文字、语音与小票附图，生成草稿后只作一句简短提示；图片模糊不猜金额。图片通过独立千问识别分支返回结构化资料，主对话仍由 DeepSeek 继续处理；识图不直接修改账本。Key 在设置的模型页填写。分析先查账本再给结论与建议，不生成写入草稿。确认卡片突出事项与金额，日期、店铺、类型与状态为辅助信息，保留确认和放弃。

同次图片录入的明细合并到一张确认卡片，点击一次全部入账，每项仍为独立账目。已打开的明细页定位到单据日期和收支归属；已入账卡片可直接查看对应日期的账目。
